001

Snake, written without an engine

A terminal game in C++ with no dependencies, and a bug that only appeared once the game became worth playing.

Language
C++17
Dependencies
None
Source
~1,400 lines
Year
2025
01 — Problem

Every project I had built until then sat on top of a framework that had already decided what a frame was, and what happened inside it. I had never written that part.

A snake game is the smallest program that still requires all of it: non-blocking input, a world on a clock, and a renderer that draws whatever the world currently is.

Get any of the three wrong and it shows immediately. That is the point of choosing it.
02 — Approach

The snake body is stored as a queue. Push a head, pop a tail, and movement becomes a data-structure decision rather than a loop over segments.

O(1) per move. Collision stays O(n), which at snake lengths is free.

It played perfectly until I got good at it. Then the snake began eating itself through corners it had already left.

03 — What broke

Collision detection ran after the render, so the check compared against the drawn frame rather than the state in memory. Below about 14 ticks per second the stale frame is on screen for 80 milliseconds and nobody notices. Above it, the snake is checked in a cell it has already left.

The fix was moving one call above another.

Loop order is not style. It decides what is true at the moment you ask.
04 — Result

Clean at every speed I can play. Because there are no dependencies it compiles to WebAssembly, so the browser build runs the same source rather than a port that drifts.

Same code in the terminal and in the browser.
