RECORD 001 / BUILD NOTE

Snake — terminal, no engine

C++17 · single binary · no third-party dependencies

AUTHOR   A. C. PRAJAPATI
DATE     2025-11-17
STATUS   SHIPPED

OBJECTIVE

Write the game loop by hand. Every prior project sat on top of a framework that had already decided what a frame was; this one answers that itself.

METHOD

Snake body stored as a queue. Movement is push-head / pop-tail, so no per-segment update and no array shuffling. Terminal is the render target — a character grid is a framebuffer if you squint.

DEFECT — ORDERING

SYMPTOM
Snake self-collides through a cell it has already vacated. Reproduces only above ~14 ticks/sec.

Collision ran after render, so the check compared against the drawn frame rather than the current state. Invisible at low tick rates because the stale frame is only on screen for ~80ms.

// game loop order
  read_input();
  advance();
- render();
- check_collisions();   // sees last frame
+ check_collisions();   // sees real state
+ render();

TAKEAWAY

Loop order is not style. It decides what is true at the moment you ask a question — and a bug that only appears once the thing is good is the most valuable kind.
