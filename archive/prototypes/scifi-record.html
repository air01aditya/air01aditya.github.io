01OBJECTIVE

Every program I had written until then sat on top of something that had already decided what a frame was, and what happened inside one. I had never written that part myself.

A snake game is the smallest thing that still needs all of it at once: input that cannot block, a world advancing on a clock, and a renderer that draws whatever the world currently is.

02METHOD

The body is a queue. Push a head, pop a tail — and movement stops being a loop over segments and becomes a choice of data structure. The terminal is the framebuffer.

03DEFECT

The snake ate itself through corners it had already left. Only above roughly fourteen ticks per second, which is why it survived every slow test.

Collision detection ran after the render, so the check was comparing against the frame on screen rather than the state in memory. At low speed the stale frame lives eighty milliseconds and nobody notices. At speed it is the difference between alive and dead.

// the entire fix
  read_input();
  advance();
- render();
- check_collisions();   // asks the screen
+ check_collisions();   // asks the truth
+ render();
04RESULT

Clean at every speed I can play. No dependencies means it compiles to WebAssembly, so the browser build runs the same source rather than a port that drifts out of sync.
